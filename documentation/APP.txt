WORDPRESS SENTINEL 0.25.0-rc1 — SCANNING AND QUARANTINE FROM A WINDOW (PROTOTYPE)

sentinel-app.py is a window for sentinel-remote.py. You fill in your site's SSH details
once, press Scan, and the report opens in your browser. A second window moves files the
scan found out of the website, and puts them back. It runs exactly the same scan as
the command line, over SSH from your computer, and keeps the sealed evidence on your
computer. Nothing is installed on the website. See REMOTE.txt for how that works.

WHAT YOU NEED

- Python 3 on your computer, from python.org. Tick "tcl/tk" during installation; it is
  ticked by default.
- SSH turned on for your hosting account, with a key. Your host's control panel has an SSH
  page that shows your username, server and port, and lets you create or upload a key.
  On SiteGround: Site Tools > Devs > SSH Keys Manager. Create a key, set a passphrase, and
  use Actions > Private Key to save it, such as into the .ssh folder in your user folder.
- Your site's folder on the server, such as /home/customer/www/example.com/public_html.
  Hosts show this in their file manager.

STARTING IT

Double-click sentinel-app.py, or run:

  python sentinel-app.py

Your entries, apart from any passphrase, are remembered in .wp-sentinel-app.json in your
user folder. Only file locations and names are kept there, never keys or passphrases.

FIRST TIME

1. Fill in the SSH username, server, port, private key file and site folder.
2. If your key has a passphrase, press Unlock key. A small window opens; type the
   passphrase there. Nothing shows as you type. This lasts until you restart the
   computer.
3. Press Test connection. The first time, it asks you to confirm the server: a window
   shows its fingerprint. If your host publishes its fingerprint, check they match, then
   type yes. After that, Test connection should say "Connected. Ready to scan."
4. Press Scan. A scan takes a few minutes. Progress shows in the window, and the report
   opens when it is finished.

AFTER A SCAN

The Latest scan buttons open the report, the timeline, the vulnerability check and the
post-incident checklist for the newest finished scan of the site that is filled in. Check
saved evidence confirms that no saved scan has changed since it was sealed.

The vulnerability check needs a Wordfence key file; see VULNERABILITIES.txt. The database
check reads the database details from wp-config.php on the server; see REMOTE.txt.

QUARANTINE: MOVING FILES OUT, AND PUTTING THEM BACK

Quarantine moves files out of your website into a private folder on your hosting
account, wp-sentinel-private in your home folder there, outside the website. Nothing is
deleted, and you can put files back. Back up your site first: removing a file that a
plugin or theme needs can break the site. Read the findings in the report before you
start, and look at any file you are unsure about.

Press Quarantine, under Latest scan. A window opens for the site filled in.

1. Make a list. Choose which priorities to include. High priority only is the default
   and the safest start. Press Make a list. Nothing on the website changes yet.
   Files WordPress needs in order to run, such as wp-config.php and anything in
   wp-admin or wp-includes, are left out unless you tick that box. They usually need a
   clean copy, not removing: see CLEAN-REPLACEMENT.txt. Findings in the database are
   left out too, because quarantine moves files only; they are often script tags added
   by page builders or analytics. What was left out shows every finding not in the
   list, with the reason. Those still need dealing with.
2. Untick any file you want to keep. Each click changes the list.
3. Press Check the list. Sentinel checks every ticked file on the server against the
   scan. Nothing changes yet. A file that has changed since the scan is a problem, and
   stops the whole list: it may mean an attacker is still active, so look at it. Untick
   it, or tick "Leave files that have changed", which leaves those where they are.
4. Press Move the ticked files. It only works after a check of exactly this list: any
   change to the ticks locks it again until you check once more. You are asked to
   confirm. Choose How many at once to go in stages, and check your site between them.
5. Check your site straight away, then scan again from the main window. Quarantine does
   not clear caches, end logins or close the way the attacker got in. Use the Checklist.

To put files back, open the Put files back tab. It lists the files this list has moved.
Tick the ones you want, press Check, then Put back the ticked files. Putting a file back
makes it active again, including any malware in it. Restore the files you need, usually
just the one the site needs to run, not the whole list.

Each list is kept with your evidence, in a quarantine folder beside the site's scans,
with a receipt of every file moved and put back. Its copy on the server is needed to put
files back, so leave wp-sentinel-private alone. Lists you made before can be opened from
List. Stopping part way is safe: files already moved stay moved, and checking the list
again carries on from where it stopped.

UNLOCKING YOUR KEY

Unlock key uses Windows' OpenSSH Authentication Agent. If the window says the agent is not
running, it needs turning on once, from a PowerShell window opened as administrator:

  Get-Service ssh-agent | Set-Service -StartupType Automatic
  Start-Service ssh-agent

Close that administrator window afterwards. Start WP Sentinel itself from a normal
window: scans made from an administrator window open as blank pages, and the app warns
you if you try. See "RUN AS ADMINISTRATOR" in REMOTE.txt.

A key without a passphrase does not need unlocking, but anyone who copies that file can
log in to your hosting account, so a passphrase is better.

IF IT GOES WRONG

"has not met this server before"  Confirm the server, as in step 3.
"refused the login"               Wrong username or key, or the key is locked: press
                                  Unlock key.
"Could not connect", or no answer Check the server name and the port. SSH is usually not
after 60 seconds                  port 21, which is FTP. SiteGround uses 18765.
Stop during a scan                The temporary .sentinel-run- folder may be left in your
                                  home folder on the server; delete it.
"Store is locked"                 A quarantine step was stopped part way. If nothing is
                                  running, see "INTERRUPTIONS" in QUARANTINE.txt.
"list's folder was not found"     Its copy on the server was removed. Make a new list.

LIMITS OF THIS PROTOTYPE

It covers scanning one site, checking evidence, opening the results, and quarantine of
the files in a scan. Scanning every site on an account, clean replacement, database
changes, alerts and scheduled runs still use the command line. Put back at most 200
chosen files at a time, or tick them all. Scans run with --unattended, so they never stop to ask a question; the
database check therefore always reads wp-config.php instead of prompting. On Mac and Linux
the window works, but Unlock key and confirming the server show a command to run in a
terminal instead.
