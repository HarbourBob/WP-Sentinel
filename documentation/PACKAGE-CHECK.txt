WORDPRESS SENTINEL 0.23.0-rc1 - PACKAGE VERIFICATION

Upload the program files directly into compat/wp-sentinel, keeping the documentation
folder beside them. Include package-manifest.json and verify-package.py. The tools
folder is not needed on a host. Replace program files while no Sentinel operation is running.
Preserve your profiles and evidence folders. Use binary/unchanged transfer mode:
line-ending conversion changes file hashes.

From compat/wp-sentinel run:

python3 -I -S verify-package.py

No profile, password, website path, network request or database connection is
needed. The verifier imports only Python standard-library modules, not Sentinel
programs. It writes nothing. It checks itself along with every listed program,
rule pack and documentation file against package-manifest.json.

package-matches: every listed file matched the expected release bytes.
package-incomplete-or-modified: inspect issues for missing or mismatched files.
verification-unavailable: manifest missing, invalid, unsafe or wrong release.
Exit codes: 0 matched, 1 discrepancies, 2 unable to verify.

Mismatches cannot distinguish old versions, intentional edits or corruption.
Upload affected files from the same complete release and check again. Unlisted
program/text entries are reported separately and never deleted or certified.
Profiles, reports, references, recovery data and website files are outside this
check. The manifest cannot include its own hash. It is not digitally signed;
this checks upload consistency, not authenticity against a same-account attacker.

If you change a packaged file, rebuild the manifest on your own computer:

python -B tools/build_manifest.py

No automatic update, scan, quarantine, deletion or scheduling is introduced.
